📊 Perbandingan: UUID v4 vs UUID v7 vs ULID vs NanoID

Identifier Panjang Karakter / Format Sortable? Standar / RFC Penggunaan Terbaik di Backend
UUID v7 ⭐ 36 char (128-bit) Hex + Hyphens (UUID standar) ✅ Ya (Time-ordered 48-bit ms) RFC 9562 (Resmi 2024) Primary Key Database modern (Postgres, MySQL). Menghindari fragmentasi B-Tree!
UUID v4 36 char (128-bit) Hex + Hyphens (UUID standar) ❌ Tidak (Acak murni) RFC 4122 / RFC 9562 Token sesi, Request ID, Correlation ID, Tracing Distributed system.
ULID 26 char (128-bit) Crockford Base32 (A-Z, 0-9 tanpa I, L, O, U) ✅ Ya (Time-ordered 48-bit ms) De-facto Open Spec Public API Identifier, URL path parameter, NoSQL key (MongoDB/Redis).
NanoID 21 char (default) A-Za-z0-9_- (URL safe) ❌ Tidak (Acak murni) Open Source Community URL shortener, invite code, ID file upload publik yang ringkas.
UUID v1 36 char (128-bit) Hex + Hyphens ⚠️ Ya (Time 60-bit 100ns) RFC 4122 (Legacy) Sistem legacy / Cassandra DB. (Hindari untuk sistem baru karena membocorkan MAC address).

💡 Mengapa Backend Wajib Beralih dari UUIDv4 ke UUIDv7 untuk Database?

❌ Masalah UUID v4 sebagai Primary Key:

  • Fragmentasi B-Tree Index: Karena UUIDv4 nilainya acak total, setiap operasi `INSERT` baru harus menyisip ke halaman index (B-tree leaf page) secara acak.
  • Page Splits Masif: Database harus sering membagi halaman memory/disk, menyebabkan cache I/O jebol dan ukuran indeks membengkak hingga 3x lipat.
  • Performa Write Drop: Pada jutaan baris data, write throughput database bisa anjlok hingga 50-80%.

✅ Keunggulan UUID v7 (RFC 9562):

  • Sequential / Monotonik: 48-bit pertama adalah Unix timestamp dalam milidetik. Data baru selalu di-insert di bagian akhir index B-tree (*append-only*).
  • Zero Page Splits: Sangat ramah engine storage seperti PostgreSQL, MySQL (InnoDB), CockroachDB, dan SQLite.
  • Kompatibilitas Penuh: Tipe data di database tetap `UUID` (PostgreSQL) atau `BINARY(16)` / `CHAR(36)` (MySQL). Tidak perlu ubah library ORM!

💻 Contoh Implementasi di Berbagai Bahasa Backend

Java 8+ / Spring Boot (Hibernate 6.2+ & FasterXML JUG) 
// 1. Menggunakan library com.fasterxml.uuid:java-uuid-generator:5.1.0
import com.fasterxml.uuid.Generators;
import java.util.UUID;

// Generate UUID v7 (Time-based sequential)
UUID uuidV7 = Generators.timeBasedEpochGenerator().generate();
System.out.println("UUID v7: " + uuidV7);

// 2. Di Entity JPA / Hibernate 6.2+:
import jakarta.persistence.*;
import org.hibernate.annotations.UuidGenerator;

@Entity
@Table(name = "orders")
public class Order {
    @Id
    @GeneratedValue
    @UuidGenerator(style = UuidGenerator.Style.TIME) // Otomatis menggunakan UUIDv7 di Hibernate terbaru
    @Column(columnDefinition = "uuid")
    private UUID id;

    // fields, getters, setters...
}
Go (github.com/google/uuid & github.com/oklog/ulid/v2) 
package main

import (
    "fmt"
    "github.com/google/uuid"
    "github.com/oklog/ulid/v2"
    "time"
    "math/rand"
)

func main() {
    // 1. UUID v7 dengan google/uuid (v1.6.0+)
    idV7, err := uuid.NewV7()
    if err != nil {
        panic(err)
    }
    fmt.Printf("UUID v7: %s\n", idV7.String())

    // 2. ULID dengan oklog/ulid/v2
    entropy := ulid.Monotonic(rand.New(rand.NewSource(time.Now().UnixNano())), 0)
    ulidId := ulid.MustNew(ulid.Timestamp(time.Now()), entropy)
    fmt.Printf("ULID:    %s\n", ulidId.String())
}
Python 3.10+ (uuid_utils atau uuid-utils) 
# pip install uuid-utils
import uuid_utils as uuid
import datetime

# Generate UUID v7
id_v7 = uuid.uuid7()
print(f"UUID v7: {id_v7}")

# Ekstrak timestamp dari UUID v7
ts_ms = id_v7.timestamp
dt = datetime.datetime.fromtimestamp(ts_ms / 1000.0, tz=datetime.timezone.utc)
print(f"Dibuat pada: {dt.isoformat()}")

# ULID (pip install ulid-py)
import ulid
id_ulid = ulid.new()
print(f"ULID: {id_ulid.str}")
print(f"ULID Timestamp: {id_ulid.datetime}")
Node.js / TypeScript (npm i uuid ulid) 
import { v7 as uuidv7, v4 as uuidv4 } from 'uuid';
import { ulid } from 'ulid';

// Generate UUID v7
const idV7 = uuidv7();
console.log('UUID v7:', idV7);

// Generate ULID
const idUlid = ulid();
console.log('ULID:   ', idUlid);

// Decode timestamp UUID v7 (Native TypeScript/JS tanpa library)
function getUUIDv7Timestamp(uuid: string): Date {
  const cleanHex = uuid.replace(/-/g, '');
  const timestampHex = cleanHex.substring(0, 12); // 48-bit timestamp
  const ms = parseInt(timestampHex, 16);
  return new Date(ms);
}
console.log('Timestamp:', getUUIDv7Timestamp(idV7).toISOString());
SQL (PostgreSQL & MySQL) 
-- 1. PostgreSQL (Postgres 17+ native uuid_generate_v7 atau pgcrypto)
-- Di Postgres 17+:
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT uuid_generate_v7(),
    email VARCHAR(255) NOT NULL,
    created_at TIMESTAMPTZ DEFAULT CURRENT_TIMESTAMP
);

-- Ekstrak timestamp dari UUIDv7 di PostgreSQL (semua versi):
SELECT 
    id, 
    to_timestamp(('x' || lpad(substr(replace(id::text, '-', ''), 1, 12), 16, '0'))::bit(64)::bigint / 1000.0) AS created_at
FROM users;

-- 2. MySQL (Disimpan sebagai BINARY(16) untuk efisiensi index maksimal)
CREATE TABLE users (
    id BINARY(16) PRIMARY KEY,
    email VARCHAR(255) NOT NULL
);

-- Insert UUID string menjadi binary:
INSERT INTO users (id, email) VALUES (UUID_TO_BIN('01921382-748a-78b1-912a-8995392cf99a'), 'user@example.com');
